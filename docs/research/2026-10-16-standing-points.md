# TaskFollow's standing points: against similar products and the native agents' own features

Written 2026-10-16 for the owner (corrected the same day after a review: what is merged vs pending is marked), who asked: *"We have to find product standing points compare to other similar products or native agent functions."* It builds on `docs/research/2026-10-16-agents-and-market.md` (OpenClaw, Hermes, Cowork, Google, small-business demand) and a second search the same day of what the native agents now do by themselves. Sources were read on 2026-10-16; secondary sources are marked. This is analysis for the owner's decisions; nothing here changes the scope by itself (section 9 and D156 stay the source).

## 1. TaskFollow's six promises, and who else keeps them

The six points are TaskFollow's pitch: guided setup for a non-technical owner, finding repetitive work, scheduled runs with a record and reasons, a code-level gate on sending, paying and deleting, an honest test of what the agent can do, and reminding the agent of skills.

| | 1 Setup for a non-technical owner | 2 Finds repetitive work | 3 Schedule, record, "why" | 4 Gate on send/pay/delete | 5 Honest capability test | 6 Skill reminders |
|---|---|---|---|---|---|---|
| **Claude Code** (routines, hooks, permissions) | No (developer-shaped) | No | **Yes**: cloud routines (research preview, Pro and up); `/schedule why…` explains a run | **Yes in code** (deny > ask > allow, hooks), **but routines run with no approval prompts** | Partial: "green status does not mean the task succeeded"; developer tools only | Model chooses from descriptions |
| **Claude Cowork + Claude for Small Business** | **Yes**: one-click connectors, a plugin, a guided setup ("pick what Claude handles", "set when each one runs") | No: a prebuilt catalog | Partial: remote schedules while the computer sleeps, past runs listed; no "why" | Partial: "by default, nothing sends or pays without your OK"; Manual / automatic (with Claude's own review) / skip modes; deleting files always asks | No | Plugins bundle skills; the model triggers them |

## 2. What is no longer a differentiator

- **Scheduling.** Every native agent schedules now, and cloud runs that don't need the computer on are the norm (Claude routines, Cowork, Codex cloud tasks, Copilot Cowork). TaskFollow should not sell "it runs on a schedule".
- **Non-technical setup on one vendor.** Claude for Small Business (launch date not on the official page; secondary sources conflict) gives a Claude subscriber one-click connectors and ready workflows. Against it, TaskFollow's setup is not easier; it is broader (any agent) and more honest (section 3).
- **Channels.** OpenClaw, Hermes, Cowork's phone push and Copilot already reach people on their phones. TaskFollow's channels stay built extras (9.8).

## 3. TaskFollow's standing points (where nobody else stands)

1. **A gate that still holds when nobody is watching, for what goes through TaskFollow.** The native code-level gates (Claude Code's ask rules, Codex's approvals) are configured by developers and, in the products' own documentation, **off for unattended cloud runs**: Claude routines run "without stopping for approval apart from some artifact actions", connectors included; Codex scheduled tasks use `approval_policy="never"` when the organisation allows it. Consumer products describe confirmations without saying whether code or the model enforces them. (Claude Code's local scheduled desktop tasks were not checked; where a native rule refuses when nobody can answer, TaskFollow's difference is that it pauses and resumes after a yes, D61, D62.)
   **What holds today:** in TaskFollow's runner, **every action that goes through TaskFollow's own tools** (a message, a record write, any step marked as needing approval) waits for a person's decision, in their terminal or by a verified Telegram reply code, bound to that exact action (D24, D58, D61, D79); the run parks and resumes after a yes. The agent's **own** tools inside a task step are limited to the step's allow-list and, in a read-only step, refused known write flags (D137, D139). **Pending:** a per-call approval for the agent's own tool, and the hook blocking when it fails, are PR #40 (D151), not merged; until then a workflow that lets a task step use the agent's own send tool is not gated. With #40 in, this is the strongest point and exactly the gap the native agents leave. One-line pitch, once #40 is merged: *"Your agent can work while you sleep. Whatever its instructions say or forget to say, it can't message a customer, pay or delete without your yes; and once you say yes, it goes."* Evidence: the plain-agent comparison (D161) found plain Claude Code keeps an explicit rule, but sends customer replies on its own when a scheduled job's instructions omit it.
2. **An honest answer to "can my agent really do this?"** No native product tests the agent's abilities for a non-technical end user and reports what it cannot do; Copilot Studio's Agent Evaluation is the nearest, for makers; neither competitor has one. TaskFollow's doability check (D156, D159) watches effects where TaskFollow is in the path (T1, T5, T7, merged) and otherwise records the person's own confirmation as *you told us* (T8, being built in 4b), and always says how it knows. Across homes, it can tell a Claude for Small Business user that their brief arrived around the scheduled time because they said so, and that "nothing sends without your OK" is the product's promise, not something TaskFollow could test (T6 can only fail an agent).
3. **Finding the work, from the owner's day.** No native "I noticed you do this often" was found anywhere; Claude for Small Business offers a catalog, not discovery. TaskFollow's interview ("walk me through your week") and the opportunity rule are the only discovery found in this field. Today the opportunity rule is mostly an instruction (level A) and "I noticed" (D148) is narrow, so **this point is real but under-built**.
4. **Not tied to one vendor, and not holding the accounts.** TaskFollow runs on the agent and subscription the person already has (9.15) and never holds their accounts; its records stay on their own machine (9.10: nothing hosted by TaskFollow's owner). Claude for Small Business and Copilot are each one vendor's catalog.
5. **The record with reasons, in its own home.** Only Claude Code's `/schedule why` explains a past run among the natives. TaskFollow's `why` shows every call with the agent's stated reason. On the agent's own scheduler TaskFollow has no record; for Cowork the check page points the person to Cowork's own run log (D158), which lists tools, not reasons.
6. **The skill the workflow needs, every run.** Everywhere else the model chooses a skill from its description; In TaskFollow's runner (Home 1), the workflow's skill text goes into the run itself (D153, D154), so a scheduled run does not depend on the model choosing right; on the agent's own scheduler the model still chooses (D158).

## 4. What this means for v1 (recommendations for the owner)

1. **Merge PR #40 first (human task 28), then lead with points 1 and 2.** The first fifteen minutes of a consult or an install should show the owner a scheduled run that **still asked them** before sending, and an **honest verdict** on their own agent, including a "no". Both exist or are being built (item 4b); item 5 (inbox triage with replies) is where point 1 becomes visible to a user.
2. **Strengthen point 3 deliberately.** Discovery is where nobody stands, and where small businesses say they are stuck (Intuit 2026: "not understanding what AI can do", 28% of US non-adopters). Item 6's interview and opportunity rule deserve more than an instruction; a concrete version (for example, the interview reading a week of the owner's calendar or inbox subjects, with their permission, and proposing the three most repetitive tasks) would be a real differentiator. This is a scope question for the owner, not a change made here, and it would reverse D148's rule that observation never sees email or messages, so it needs the owner's explicit yes on that point.
3. **Treat Claude for Small Business as the reference to beat, and as a possible host.** For a Claude subscriber, TaskFollow should add what it lacks: the gate in unattended runs, the honest check, discovery. Through Home 2 (D158), TaskFollow can deliver workflows *into* Cowork and still say plainly what holds there.
4. **Keep the comparison test.** The plain-agent comparison (`docs/testing/2026-10-16-plain-agent-comparison.md`) tests point 1 directly: does plain Claude Code keep "never send without asking me" when a trick email says otherwise, in a scheduled run? Arm A runs by hand a run that stands in for the scheduled one; it does not execute a real unattended run, so a pass there says less than the pitch needs.
5. **Say the limits plainly.** The gate holds only for actions that go through TaskFollow (9.2) until #40 adds the agent's own tools in task steps; on the agent's own scheduler (Home 2) TaskFollow is not in the path. The pitch must never imply more.
